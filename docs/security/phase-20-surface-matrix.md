# Phase 20 attack-surface inventory

Recorded before implementation on the Phase 20 branch. This is the baseline review matrix; final controls and findings are recorded in phase-20-security-review.md. Sources are route/page files and their service/repository guards, not UI visibility.

## Trust boundaries

All browser bodies, identifiers, queries, headers, prices, roles, upload metadata and unsigned provider payloads are untrusted. Firebase verifies identity only. Current PostgreSQL user/activity, membership, organization status and LocationAccess establish staff scope. Hash lookup plus current expiry, operational seat and live screening establish anonymous customer scope. Payment price/context comes from the transactional database; only a verified provider event can settle. Shared PostgreSQL counters and server job secrets are operational controls, not authority to bypass business guards.

No application Server Actions, service worker, arbitrary HTML renderer, arbitrary remote-image import or tenant-configured outbound webhook surface was found in the initial source search. Internal bootstrap, migration, seed, verification and capture scripts are local operator tools, not HTTP routes; they must not be exposed by hosting. Firebase client password/reset requests are external identity-provider calls; CineBite never receives passwords.
